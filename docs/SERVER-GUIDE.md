# Serveur POSR — bonnes pratiques

Pour gérants et responsables. Installation technique : support ou intégrateur.  
Word : [`Guide-bonnes-pratiques-serveur.docx`](Guide-bonnes-pratiques-serveur.docx)

## Le serveur, en bref

Machine qui centralise les données (commandes, menu, employés, stock). Caisses et tablettes s’y connectent en réseau.

## Comptes

- Un PIN ou mot de passe par personne — jamais de code commun.
- Changer les codes par défaut le jour J.
- Désactiver le compte le jour où quelqu’un quitte.
- Donner le minimum de droits (caisse, cuisine, admin).
- Verrouiller ou se déconnecter si le poste est laissé seul.

**Mots de passe admin** — réservés au gérant ou 1–2 responsables ; pas de post-it, pas de groupe WhatsApp.

## Sauvegardes

- Automatique : au moins une fois par jour.
- Contrôler une fois par semaine qu’un fichier récent existe.
- Copie hors restaurant.
- Manuelle avant toute mise à jour majeure.

## Réseau et machine

- Serveur dans un local fermé.
- Tablettes sur le Wi‑Fi staff, pas clients.
- Ne pas éteindre le serveur pendant le service.
- Pas de logiciels perso sur la machine serveur.

## Chaque service

**Ouverture** — test connexion, commande test, ticket cuisine, ticket caisse.

**Fermeture** — clôture caisse / journée selon votre procédure.

## Mise en service

- [ ] Codes par défaut changés  
- [ ] Comptes et rôles créés  
- [ ] Menus, tables, paiements, imprimantes  
- [ ] Parcours commande → cuisine → paiement → ticket  
- [ ] Sauvegarde vérifiée  
- [ ] Équipe formée  

## Pannes

| Problème | Action |
|----------|--------|
| Connexion impossible | Wi‑Fi staff ? Serveur allumé ? Ne pas créer de comptes au hasard. |
| Cuisine sans commandes | Écran + réseau, commande test, support si > 10 min. |
| Pas de ticket | Papier, alimentation, câble, impression test. |
| Carte refusée | Terminal + Internet ; procédure espèces si définie. |
| Coupure de courant | Attendre redémarrage serveur, commande test. |
| Internet coupé | Vendre si la caisse répond ; noter l’heure, support si anormal. |

## À ne pas faire

- Compte « directeur » partagé.
- Ignorer alertes sauvegarde / connexion plusieurs jours.
- Redémarrer tout en plein service sans raison.
